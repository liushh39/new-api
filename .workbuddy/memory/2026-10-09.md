# 2026-10-09 工作记录

## new-api 本地前后端跑通（非 Docker）

目标：不用 Docker，本地起后端 + 前端。

### 环境事实（重要）
- Go 1.27.1、bun 1.4.2、node v22.22.2 均可用。
- `main.go` 使用 `//go:embed web/dist/index.html`，**必须先构建前端**，否则 `go build` 编译失败。
- `web/dist` 被 gitignore，需要本地构建产出。
- 后端默认：SQLite（`one-api.db`，WAL）、端口 3000、无 Redis 时走内存缓存；无需 `.env` 即可启动。

### 遇到的坑：node_modules 文件损坏
- 现象：`bun run build` 报 `@base-ui/utils` 的 `reactVersion.mjs` 无法解析、`useValueAsRef.mjs` 是 765 字节全 `\0` 的坏文件。
- 排查：`~/.bun/install/cache` 里的包内容是**完好的**，说明损坏发生在写入 node_modules 阶段。
- 修复：`bun install --force`（从缓存重新解包，1193 个包，约 14 分钟）。不要清 cache，cache 是好的。
- 注意：`rm -rf node_modules/...` 会被 safe-delete 钩子拦截（文件数超阈值需确认），优先用 bun 自身机制修复。

### 启动命令（已验证）
```bash
# 1. 前端依赖 + 构建产物（embed 依赖）
cd web && bun install && bun run build

# 2. 编译后端
go build -o new-api-dev.exe .

# 3. 起后端（端口 3000）
./new-api-dev.exe

# 4. 起前端 dev（端口 5173，代理 /api /v1 /mj /pg -> 3000）
cd web && bun run dev -- --host 0.0.0.0 --port 5173
```
- 关键点：rsbuild dev 默认端口是 3000，会与后端冲突，**必须显式指定 5173**。

### 验证结果
- 后端 `GET http://localhost:3000/api/status` → 200
- 前端 `GET http://localhost:5173/` → 200，title = New API
- 代理 `GET http://localhost:5173/api/status` → 200
- 数据库为全新库，日志提示 "system is not initialized and no root user exists"，首次访问需走初始化向导创建管理员。
- 首次 Go 全量编译耗时约 23 分钟（modernc sqlite 体量大）。
